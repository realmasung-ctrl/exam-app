# คู่มือดูแลระบบ: สำรอง กู้คืน และแก้ปัญหาเฉพาะหน้า

## 1. นโยบายการสำรองข้อมูล (สำคัญที่สุด)
Supabase แพ็กเกจฟรี **ไม่มีการสำรองข้อมูลอัตโนมัติ** ถ้าฐานข้อมูลเสียหรือถูกลบ ข้อมูลกู้คืนได้เฉพาะจากไฟล์ที่คุณเก็บเอง

| เมื่อไร | ทำอะไร |
|---|---|
| ทุกครั้งหลังจบรอบสอบ | เมนู “ตรวจสอบระบบ / สำรองข้อมูล” → ดาวน์โหลดไฟล์สำรอง + ส่งออก Excel ของรอบนั้น (หน้า “ผลสอบ”) |
| ทุกสัปดาห์ที่มีการใช้งาน | ดาวน์โหลดไฟล์สำรอง (ตั้งเตือนในปฏิทิน) |
| ก่อนอัปเดตระบบ/แก้ไขชุดข้อสอบจำนวนมาก/ลบรอบสอบ | ดาวน์โหลดไฟล์สำรอง |

หลักปฏิบัติ: เก็บอย่างน้อย **2 ที่** (เครื่องคอมพิวเตอร์ + ไดรฟ์องค์กร) · เก็บย้อนหลังอย่างน้อย 3 เวอร์ชัน · ไฟล์มีชื่อผู้เข้าสอบ เฉลย และคะแนน จึงบีบอัดเป็น zip ตั้งรหัสผ่าน และจำกัดคนที่เข้าถึง · สำรองตอนไม่มีรอบสอบที่กำลังสอบอยู่ · ทดลองกู้คืนจริงอย่างน้อย 1 ครั้งก่อนใช้งานจริง (ข้อ 2.3)

ตรวจไฟล์สำรองว่าใช้ได้ (ไม่ต้องมีฐานข้อมูล): `node scripts/restore-backup.mjs ไฟล์.json --dry-run` — ถ้าไฟล์ถูกตัดกลางคันหรือเสีย จะบอกทันที

## 2. การกู้คืน
ต้องมี Node.js 18+ และกุญแจ `service_role` ของโปรเจกต์ปลายทาง สคริปต์ไม่ต้องติดตั้งแพ็กเกจ

### 2.1 กรณีลบรอบสอบ/ชุดข้อสอบผิด (โปรเจกต์ยังอยู่)
```powershell
$env:SUPABASE_URL="https://xxxx.supabase.co"
$env:SUPABASE_SERVICE_ROLE_KEY="service_role key"
node scripts/restore-backup.mjs backup.json --dry-run          # ตรวจไฟล์
node scripts/restore-backup.mjs backup.json --yes --merge      # เขียนทับแถวที่ id ตรงกัน เติมแถวที่หายไป
```
`--merge` จะ **เขียนทับ** แถวที่มี id เดียวกันด้วยค่าจากไฟล์สำรอง (ข้อมูลที่แก้หลังวันที่สำรองจะถูกแทนที่ในแถวนั้น) แถวอื่นไม่ถูกลบ

### 2.2 กรณีโปรเจกต์เสียหายทั้งหมด / ย้ายไปโปรเจกต์ใหม่
1. สร้างโปรเจกต์ Supabase ใหม่ (DEPLOY.md หัวข้อ 2): เปิด pg_cron → รัน migration **0001–0005** → ปิดการสมัครสาธารณะ
2. สร้างผู้ดูแลคนแรก (DEPLOY.md หัวข้อ 3) — บัญชีผู้ดูแลไม่อยู่ในไฟล์สำรอง
3. รันสคริปต์กู้คืนโดยไม่ต้องใส่ `--merge` (โปรเจกต์ใหม่ว่างเปล่า) : `node scripts/restore-backup.mjs backup.json --yes`
4. Vercel → แก้ `SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` เป็นของโปรเจกต์ใหม่ → Redeploy
5. ตรวจ: เมนูตรวจสอบระบบ ทุกรายการ ✅ · หน้าผลสอบของรอบเก่ายังเห็นครบ · เปิดลิงก์/QR ของรอบเก่าในมือถือ (รหัสรอบสอบถูกกู้คืนด้วย ลิงก์เดิมจึงใช้ได้) · รัน `security.sql`

สิ่งที่สคริปต์ทำ: เขียนทีละตาราง (แม่ก่อนลูก) ครั้งละ 200 แถว · ถ้าเกิดข้อผิดพลาดจะหยุดและบอกสาเหตุ (รันซ้ำได้ ปลอดภัย) · สุดท้ายนับแถวเทียบกับไฟล์ · ช่อง “ผู้สร้าง” ของชุดข้อสอบ/รอบสอบถูกล้างเป็นว่าง (เพราะบัญชีผู้ดูแลเดิมไม่มีในโปรเจกต์ใหม่)

### 2.3 ซ้อมกู้คืน (ทำก่อนใช้งานจริง)
สร้างโปรเจกต์ Supabase ทดสอบ (ฟรี) → รัน migration → กู้คืนไฟล์สำรองจริงเข้าไป → ดู SQL Editor ว่าจำนวนแถวตรง ถ้าทำไม่ได้ในวันนี้ ก็ยังไม่ควรเชื่อว่าสำรองไว้ได้จริง

## 3. สถานการณ์เฉพาะหน้า
| อาการ | สาเหตุที่พบบ่อย | แก้อย่างไร |
|---|---|---|
| ผู้เรียนบอก “ไม่พบรอบสอบ” | ลิงก์ผิด/ตัวอักษรหาย, รอบสอบถูกลบ, `NEXT_PUBLIC_APP_URL` ผิดโดเมน | เทียบลิงก์ในหน้ารอบสอบ กด “เปิดหน้าสอบ” ทดลอง ; ตรวจหน้า “ตรวจสอบระบบ” |
| “รอบสอบนี้ปิดรับผู้เข้าสอบแล้ว” | ปิดรับ/ถึงเวลาปิดรับ/สิ้นสุดรอบ | หน้ารอบสอบ → “เปิดรับผู้เข้าสอบอีกครั้ง” (ถ้ามีเวลาปิดรับให้แก้เวลาด้วย) |
| “ชื่อนี้เข้าสอบรอบนี้ไปแล้ว” | พิมพ์ชื่อซ้ำ / เปลี่ยนเครื่อง / ล้างคุกกี้ / ปิดเบราว์เซอร์ในโหมดส่วนตัว | ผลสอบ → รอบนั้น → “อนุญาตสอบใหม่” (ได้เวลาเต็มอีกครั้ง ผลเดิมเก็บไว้แต่ไม่แสดงในรายงาน) |
| โทรศัพท์ผู้เรียนดับ/แบตหมด กลางการสอบ | — | เปิดลิงก์เดิมในเครื่องเดิมและเบราว์เซอร์เดิม ทำต่อได้ (เวลายังเดินอยู่) ; ถ้าเปลี่ยนเครื่อง → อนุญาตสอบใหม่ |
| เน็ตของทั้งห้องหลุด | — | คำตอบที่เลือกแล้วบันทึกไว้ที่เซิร์ฟเวอร์ ; เมื่อกลับมาต่อได้ ; ระบบส่งอัตโนมัติเมื่อหมดเวลาแม้ไม่มีใครเปิดหน้า |
| กด “สิ้นสุดรอบสอบ” ผิด | — | **ย้อนไม่ได้** ผู้ที่กำลังสอบถูกส่งตามคำตอบล่าสุด ให้สร้างรอบสอบใหม่และ (ถ้าจำเป็น) ให้ผู้ที่ได้รับผลกระทบสอบใหม่ |
| พบว่าเฉลยหรือคำถามผิดหลังเปิดรอบแล้ว | รอบสอบใช้สำเนาข้อสอบ ณ ตอนเปิด แก้ไม่ได้ (ตามข้อกำหนดเพื่อให้ผลสอบถูกต้อง) | แก้ที่ชุดข้อสอบต้นฉบับ แล้วเปิดรอบใหม่ ; ถ้าต้องคิดคะแนนรอบเดิมใหม่ ต้องให้ผู้พัฒนาเพิ่มฟังก์ชัน “ตรวจใหม่” (ยังไม่มี) |
| ลืมรหัสผ่านแอดมิน | — | Supabase → Authentication → Users → เลือกผู้ใช้ → ส่งอีเมลรีเซ็ต/ตั้งรหัสใหม่ ; ผู้ดูแลคนอื่นรีเซ็ตให้ในระบบไม่ได้ |
| ล็อกอินแล้วเด้งกลับ “ไม่มีสิทธิ์ผู้ดูแล” | มีบัญชีใน Supabase แต่ไม่มีแถวใน admin_profiles | เพิ่มแถวด้วย SQL (DEPLOY.md หัวข้อ 3) |
| เว็บช้าผิดปกติ | Function Region ไกล / Supabase ช้า | หน้าตรวจสอบระบบดู “ความเร็วติดต่อฐานข้อมูล” และ “ตำแหน่งเซิร์ฟเวอร์” |
| เว็บขึ้น error ทั้งระบบ | โปรเจกต์ Supabase ถูกหยุด (ไม่มีการใช้งานนาน) | Supabase Dashboard → Restore project (ข้อมูลยังอยู่) ; ตรวจว่างาน cron ใน Vercel ยังทำงาน |
| อัปเดตแล้ว build ล้ม | โค้ดผิด/ไฟล์อัปโหลดไม่ครบ | Vercel → Deployments → Promote ตัวก่อนหน้าที่ Ready ; ส่งบรรทัดแดงของ build ให้ผู้พัฒนา |

ดูบันทึกข้อผิดพลาด: Vercel → โปรเจกต์ → Logs (กรอง Error) · Supabase → Logs

## 4. ลำดับงานวันสอบ
**ก่อนวันสอบ (1–2 วัน)**: สำรองข้อมูล · เมนูตรวจสอบระบบเป็น ✅ · สร้างรอบสอบและเปิด · ทดลองสแกน QR ด้วยมือถือ 2 เครื่อง · ทำข้อสอบทดลองตั้งแต่เริ่มจนจบ ตรวจคะแนนด้วยมือ · ลบผู้เข้าสอบทดลองออก (สร้างรอบสอบใหม่สำหรับวันจริงแทนการใช้รอบทดลอง)
**30 นาทีก่อนสอบ**: เปิดรอบสอบ · ตรวจว่าข้อความโหมดเฉลยถูก · ฉายหรือแจก QR · เตรียมเบอร์ผู้ดูแลสำหรับปัญหาเฉพาะหน้า
**ระหว่างสอบ**: เปิดหน้า “ผลสอบ” ของรอบนั้นดูสถานะ (อัปเดตเองทุก 5 วินาที) · ผู้มาสายให้สแกนได้จนกว่าจะ “ปิดรับผู้เข้าสอบ”
**หลังสอบ**: “ปิดรับผู้เข้าสอบ” → ตรวจว่าทุกคนส่งแล้ว (หรือหมดเวลา) → “สิ้นสุดรอบสอบ” → ส่งออก Excel → ดาวน์โหลดไฟล์สำรอง → ค่อยลบรอบทดลอง/รอบเก่าที่ไม่ใช้

## 5. ข้อมูลส่วนบุคคลและการเก็บข้อมูล
ระบบเก็บชื่อ-นามสกุล รหัสประจำตัว (ถ้ากรอก) คำตอบ และคะแนน แนะนำ: แจ้งผู้เข้าสอบว่าเก็บข้อมูลอะไรเพื่ออะไร · กำหนดระยะเวลาเก็บ (เช่น ส่งออกเก็บตามกฎขององค์กรแล้วลบรอบเก่าออกจากระบบ ที่หน้า “ผลสอบ”) · ไฟล์สำรองและไฟล์ส่งออกก็เป็นข้อมูลส่วนบุคคลเช่นกัน ลบเมื่อพ้นกำหนด · เอกสารนี้ไม่ใช่คำแนะนำทางกฎหมาย ให้ปรึกษาผู้รับผิดชอบด้าน PDPA ขององค์กร

## 6. ข้อจำกัดที่ทราบ
- ไม่มีสำรองข้อมูลอัตโนมัติ (ข้อ 1) · ยังไม่มีการจำกัดจำนวนคำขอต่อ IP · ยังไม่มี CSP · ไม่มีฟังก์ชัน “ตรวจใหม่” หลังเปิดรอบ · ผู้เรียนเปลี่ยนเครื่องกลางการสอบต้องให้แอดมินอนุญาตสอบใหม่ · ไม่มีการสุ่มข้อ/ตัวเลือก · รายงาน PDF เฉพาะทาง (ใช้พิมพ์เป็น PDF จากเบราว์เซอร์แทน) · แอดมินสองคนแก้ชุดข้อสอบเดียวกันพร้อมกัน คนที่บันทึกทีหลังทับของคนแรก
